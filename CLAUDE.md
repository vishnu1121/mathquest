## Architecture rules

- `src/adventure/` is the current game. `runtime/` holds plain-JS modules (ported from the playtest prototype) that attach namespaces to `window` and are loaded in order by `runtime/index.js`; `AdventureRoot.tsx` renders the static `Shell.tsx` and starts `MQ.start()` once. Styles are global CSS in `styles/`, imported in cascade order by `AdventureRoot.tsx`.
- The runtime never calls a model directly: `runtime/core-ai.js` posts to `/api/adventure-ai`, which uses `src/ai/adventure/` (zod schemas, frozen prompts, reply validators) and `src/ai/server/provider.ts`. The API key stays on the server.
- **The model provider is configuration, not code.** `src/ai/server/provider.ts` picks an adapter from `AI_PROVIDER` (`anthropic` by default, or any OpenAI-compatible provider: openai, groq, openrouter, together, gemini, ollama, custom) using `AI_API_KEY`, `AI_MODEL` and, for `custom`, `AI_BASE_URL`; `ANTHROPIC_API_KEY` alone still selects Anthropic. `anthropic.ts` keeps the SDK extras (prompt caching, server-side fallback, effort); `openaiCompatible.ts` is plain `fetch` with `z.toJSONSchema`, falling back to plain-JSON mode when a model cannot take a strict schema, so no new dependency is needed. Prompts, guards, validators and routes stay provider-unaware, and every reply is still re-checked by the same zod schema and validators. Disclose whichever provider and model ship (hackathon Rule 7.6).
- `src/engine/` is pure TypeScript: no React, no network, no AI, and no direct `Date.now()` or `Math.random()` (inject a clock and the seeded RNG). It powers `/classic`, and the adventure uses it through the tested adapters in `src/adventure/` (`learning.ts`, `riverLearning.ts`).
- `src/game/` is the React UI of the original MVP (`/classic`).
- Current AI is optional and writes bounded narrative, hints, explanation feedback and notes through eleven tasks, including the Muddle Monster Arena's `diagnose` (a misconception code, used only for answers the rules in `arenaMath.ts` cannot classify) and `companion` (Hoot's one-sentence question about what the child is doing right now: a pause, a mix-up, a boss move or a request for help; code picks the moment). It does not execute actions or invent rules; an accepted diagnosis only selects a code-checked boss mechanic. This describes the implementation, not a restriction against the owner's requested active-AI direction. Future actions/generated boards need bounded schemas and code checks for legality, solvability and mathematical correctness. The eleventh is `explain` ("You wanna know how?"): a step-by-step walk-through of a question the child has ALREADY answered and the game has ALREADY scored, so nothing it says can change a result. It runs on a SECOND provider account — `EXPLAIN_AI_*` in `ai/server/provider.ts`, with no fallback to the default key — so a curious class cannot drain the key hints and coaching share. It is offered only where the answer is a single value the closing line can be checked against; the server drops any explanation that ends on a different answer than the code computed.
- The twelfth is `generate`: a FRESH question to replace a built-in one, so replaying a quest is not replaying the same five questions. This is the one task where the model produces mathematics rather than describing mathematics the code already did, so it is the one task with a solver behind it: the model must return its working as a flat program, and `ai/adventure/generate.ts` runs that program in exact rational arithmetic and drops the question unless the result is the answer the model declared. Picture-led boards (ten frames, clocks, coins, arrays, fraction bars, world puzzles) are never sent, because their question lives in the picture. It runs on a THIRD and FOURTH account — `GEN_AI_*` then `GEN2_AI_*`, tried in that order, with no fallback to the other keys — and the browser always holds the built-in question for the round already, so a dead key, a timeout or a rejected reply costs nothing and stalls nothing. **Never await generation on the critical path**; `runtime/question-source.js` prefetches one round ahead.
- **Apex Mode** (`classes/apex.ts`, `runtime/apex.js`, `styles/apex.css`) is Grades 3-5 ONLY and opens only when every chapter of that class is finished; K, 1 and 2 have no Apex tab and no Apex levels registered. It replays the same eight chapters at the hardest that grade goes, with a code-enforced two-step floor on generated questions and a code-chosen 5-15% of rounds reaching one grade up (labelled to the child, and excluded from the learner model). Apex level ids are `apex-<chapterId>` and live OUTSIDE the catalog so nothing that counts eight chapters sees them; every Apex level must set `pathway: true` or the legacy three-stop map throws. Seven rare gems plus the Nova Gem are earned by how well a quest is played, never by chance; `apex` is a per-class `CLASS_FIELD`.
- Preserve built-in play and honest AI status. Math scoring, stars, badges and progression remain code.
- **Every AI job has a first-choice account and an understudy**, paired in `ai/adventure/chain.ts`: `AI_*`/`AI2_*` (general), `HINT_AI_*`/`HINT2_AI_*` (Hoot's hints), `EXPLAIN_AI_*`/`EXPLAIN2_AI_*` (the explainer), `GEN_AI_*`/`GEN2_AI_*` (fresh questions). `askChain` asks each in turn and takes the first reply the task's OWN validator accepts, so a reply that fails the guard is treated like a provider that did not answer. Understudies are optional; with one unset that job simply has a single account. Hints fall back to the general accounts when no hint account is configured, so an older install keeps working. Each lane has its own rate-limit bucket.
- Current server model and beta options are inherited, unverified configuration; check provider/account compatibility before claiming live AI works. Never print keys or initiate a paid test merely because a key becomes available.
- Classes live in `src/adventure/classes/` (pure TypeScript, seeded RNG):
  - `tasks.ts`: task shapes, answer parsing, `checkTask` and `validateTask`.
  - `reference.ts`: the Practice view's maths cards — static, one rule and one worked example each. No AI. `reference.test.ts` re-solves every equation on every card and checks each card's standard against the standards that class's own chapters cite, so a card cannot be wrong or off-grade.
  - `families*.ts`: the question generators.
  - `catalog.ts`: the six classes, their chapters, stories, practice and skill names.
  - `progress.ts`: the per-class save swap.
  - `apex.ts`: Apex Mode for Grades 3-5 — unlock rule, the eight quests, the stretch ratio, the gem table and the award rule. Pure and seeded; no randomness in gem awarding.
  - The runtime is `class-visuals.js` (pictures), `class-games.js` (chapter, practice and Apex levels), `question-source.js` (fresh questions, prefetched, with the built-in one always in hand), `apex.js` (`MQApex`: the Apex panel, the vault, the reveals) and `classes.js` (`MQClasses`: picker, switching, unlock rules).
  - A chapter opens only in its own class and in slot order; finished chapters can always be replayed. Existing chapters keep their slot, so the bonus game for each slot is unchanged.
  - `switchClass` stores `CLASS_FIELDS` under `classes[grade]`. Story books and bonus records belong to the class. Coins, badges, cosmetics, the camp and keepsakes are shared.
  - Every new question must pass `validateTask` and the seeded tests in `classes.test.ts`. The runtime never decides correctness.
- Latest game rules are in `frontier.ts` and `voyage.ts`; adult evidence is in `progressReport.ts` (class-aware when a class is chosen). Runtime entry points are `frontier-games.js`, `frontier-minis.js`, `dream-lab.js`, `adult-dashboard.js` and `voyage-world.js`. See the project-state architecture table before extending them.
- Keep `mq.playtest.v3` save compatibility. Independent and supported attempts remain distinct across reloads; arcade scores and chapter stars do not establish mastery. `storyShelf`, `storyLevel` and `dreamProgress` are left in `CLASS_FIELDS` on purpose after Story Lab's removal: nothing writes them any more, and leaving them keeps an existing save's class switching exactly as it was.
- Characters: Hoot the Owl helps. Pip the sprite is a fellow learner with three authored mistakes in the existing teaching activity; Nimbus is the lost storm; Nimbus appears from Grade 2 onward, and story choices such as the Skyrail promise belong to one class. Tinker runs the robot workshop. Keep the roles coherent. All hero options stay unisex.

## Hard constraints (hackathon rules)

- No GPL, LGPL, AGPL or SSPL dependencies; MPL, EPL and CDDL need review. `npm run audit:licenses` must pass.
- No Tailwind (its lightningcss dependency is MPL-2.0). Never use `next/image`; `sharp` is replaced by `vendor/sharp-stub`.
- No biometrics, camera, microphone, emotion inference or real child data. Learner state stays in browser storage (`mq.playtest.v3`).
- System fonts, emoji and hand-written SVG/CSS only; no third-party font, image or audio files. Sounds are synthesized with Web Audio.

## Design system

- Classic MVP tokens live in `src/app/globals.css`; adventure layers live in `src/adventure/styles/`. `AdventureRoot.tsx` owns the cascade, and the tail of it matters: `theme.css` (grade tokens), then `natural-world.css` (the other agent's sea, nav palette and grove), then `chrome-blend.css` (the blended top bar) last. A change that appears not to build is usually losing to one of these on specificity — `chrome-blend.css` anchors on `#app` for exactly that reason. Hoot's companion bar (`runtime/companion.js`) is shared by every level: levels report what the child is working on with `api.companion.watch(() => ({ sees, nudge }))`, and unprompted lines must never state an answer. Runtime code is excluded from ESLint; verify affected gameplay in the browser. Avoid global-style leakage and stale asynchronous writes after leaving a level.
- Right and wrong are never shown by color alone: always icon or shape plus words (plus sound). Touch targets are at least 48px, text at least 14px. Respect reduced motion and the in-game calm mode; only the world shakes, never controls.
- Arcade layer (`runtime/arcade.js`, rules in `src/adventure/arcadeScore.ts`): points reward correct answers and streaks of them, never speed. A miss only resets the streak; points are never taken away. Pop words and banners stay decorative or are announced politely, and calm mode turns off music, shakes, flashes and hit-stops.
